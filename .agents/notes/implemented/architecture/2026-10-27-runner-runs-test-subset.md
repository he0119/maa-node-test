# Agent Note: 由 maa-tools 收集、选择和判定，扩展显示结果

Status: implemented

## Problem

开发时常只想验证一个文件或一条用例。选择范围后，测试须执行完整断言，结果也要准确返回源文件中的用例。按组名、截图名或期望节点猜来源，会把同名组、复用截图和不同识别框的用例混在一起；过滤后再算待检查节点，还会漏掉本来不该命中的节点。

扩展若自己校验运行文件、猜测日志、重新比较识别框或定义整批结论，就需要和命令行各维护一套规则。缺图或没有返回结果时，两边可能给出不同结论。

## Decision

- VS Code 宿主职责分别放在 [testRunner.ts](../../../../src/testRunner.ts)、[testController.ts](../../../../src/testController.ts) 和 [toolVersionStatus.ts](../../../../src/toolVersionStatus.ts)，宿主类分别为 `NodeTestRunner`、`NodeTestExplorer`、`MaaToolsVersionStatus`。普通数据与文字转换不创建宿主对象，逐文件职责集中维护在 [reference](../../../skills/maa-node-test-dev/reference.md#文件职责)。
- [collect.ts](../../../../src/maatools/collect.ts) 的 `collectTests()` 与 [run.ts](../../../../src/maatools/run.ts) 的 `startMaaToolsRun()` 直接共用 [process.ts](../../../../src/maatools/process.ts) 的进程读取；命令参数归 [command.ts](../../../../src/maatools/command.ts)，机器结论类型归 [protocol.ts](../../../../src/maatools/protocol.ts)，显示标记计划归 [testMarks.ts](../../../../src/core/testMarks.ts)，运行标题与摘要归 [runSummary.ts](../../../../src/core/runSummary.ts)。这让进程读写、机器数据与界面显示各有明确修改位置。
- 使用被测仓库的 maa-tools 命令入口。扩展收集调用 `test --list --json`，扩展所有运行调用 `test --jsonl`；两者加载同一份配置与 `test.cases`，收集不初始化 MaaFramework。收集与运行先读取已安装包版本，只接受稳定版 `>=1.2.0 <2.0.0`，允许 `v` 前缀和构建元数据，不接受预发布、未知或格式无效的版本；每次操作不额外执行 `--version`，仍检查实际启动和返回数据。
- maa-tools 版本放在主状态栏左侧，与 MaaSupport/MaaFramework 一样使用默认优先级，显示无图标的版本文字。被测仓库有配置或工具包即常显，点击整项刷新，悬浮保留完整来源；普通项目隐藏。状态栏优先使用 `--version`，查询与兼容提示共用结果，支持自动刷新、防抖和迟到保护；运行数量状态项使用 priority 100。
- 只支持文件测试。框架读取测试 JSON 时自动给每条用例记录 `origin`，包含实际文件绝对路径与原始下标；原始 JSON 不用手写 origin。展开后的 `TestCases.cases.origin` 与 `TestCaseRunResult.origin` 在类型和运行时都必填，loader 必须保留，动态生成的展开对象也须关联实际文件和下标。缺少、无效或无法对应文件与下标的来源在加载计划阶段报 `test-source-invalid`，不进入识别。Windows 来源路径按不区分大小写的规范化路径匹配、去重与对账，其他系统区分大小写；显示路径保留原有大小写，组名只用于显示。
- 框架在用例选择前固定完整待检查节点。只跑一条截图，仍检查同组完整节点集合；没有识别结果不能默认为负例通过。
- 框架公开报告由 `status`、`files`、`durationMs` 和可选的 `errorCode`、`reason` 构成。平台结果位于所属文件用例的 `platforms[].result`。文件结果包含计划下标 `selectedCases` 和全部对应结果；缺图、无有效检查和无匹配有明确状态与原因。框架按执行组展开、固定完整节点、调度和并行判定，普通文本日志显示组名和结果。扩展检查必需结构、类型、来源、所选下标、结果覆盖、汇总与最终一致性，不重新判定。
- 运行标准输出每行一个 JSON：三类开始/完成事件后，最后唯一一条 `run-result` 包含完整报告；人类日志走 stderr。普通 `--json` 输出一份运行报告，`--list --json` 输出一份收集清单；单独 `--list` 显示人类列表，不解析人类日志猜进度。
- 框架在每张图的全部节点块完成后判定对应用例；同一来源在本次实际计划中的全部平台完成后，才发用例完成结果，文件全部所选用例完成后再发文件结果。即时快照复用同一报告逻辑，只带对应范围的 `files`；加载计划失败时只返回最终错误报告，不伪造识别开始。
- 测试树文件名旁只显示组名，用例优先显示非空名称、其次截图名或序号；普通用例不重复图片、节点数和平台资源组合。灰字保留负例、缺图和读取失败等短提示；树节点不设置额外 tooltip，完整错误仍放在错误详情中，平台及预期节点可查看源文件和测试输出。
- 面板先排队，收到识别开始事件才标运行中，收到完整且通过校验的完成结果就结束对应节点，不等整批末尾。最终结果补未报告项，并与已显示的结果核对。
- 多个完整文件合为一次运行以减少重复准备。排除个别用例时只提交剩余用例，接受额外调用开销；先保证范围正确，再考虑批量优化。
- 真实识别任务按组内绝对截图路径去重，复用耗时在对应所选用例间分摊。用例与文件显示识别执行时间，整次运行显示实际经过的时间。
- 扩展不另起运行脚本，不读取文本日志或错误明细文件推算结论。本地解析仅服务于 CodeLens、补全、悬浮等编辑辅助；截图预览和黄线不是实际运行依据。

## Alternatives considered

**在扩展中实现测试规则。** 资源准备、并行调度、识别判定和结果汇总由框架统一实现，命令行与编辑器使用同一套规则。扩展的数据转换围绕 VS Code 显示需求组织。

**使用显示信息关联用例。** 组名、图片和节点可能重复，不能提供稳定身份。文件绝对路径与原始下标由文件加载器生成，可用于选择、进度关联和结果定位。

**为每个文件独立准备进程。** 配置加载和 MaaFramework 准备有固定开销。完整文件按批次提交给框架，框架通过逐用例、逐文件事件提供及时显示，并复用识别准备与任务。

**解析人类日志生成结果。** 日志文案面向阅读；结构化事件明确规定类型、来源、结果和结束记录，供调用方检查。普通 `--json` 适合单份报告，`--jsonl` 提供运行中的逐项结果。

## Consequences

- 命令行和扩展采用同一套框架判定，来源匹配使用文件绝对路径与原始下标。
- 无文件错误且过滤后本次 cases 为空时，文件记 skipped，原因是 no-cases-selected，进度和最终结果一致，面板标跳过；它不影响其他文件真实通过或失败，全空仍为 empty。有所选用例时，全缺图或没有有效检查仍是文件 error；部分平台缺图而其他平台完成验证时可 pass，不能仅从聚合用例均 skipped 推断全缺图。
- 自定义 loader 必须保留 `origin`，动态生成的展开对象也须关联实际测试 JSON 文件和原始下标；缺少或错误来源在加载计划阶段拒绝。文件结论先看用例 fail，再看文件 error 或用例 error；整批以 error 优先。
- 包版本只决定是否支持这套接口，不能证明命令可运行。编辑辅助解析和未知字段检查不能代替运行结果的来源类型与身份校验。扩展检查必需结构、合法记录 `type`、来源和计划结果覆盖；缺失结果要报错，不填绿色通过。
- 1.x 内可增加调用方无需处理的可选字段；改名、删除必需字段、改变类型或结论语义，以及增加调用方必须处理的新 `type` 或枚举值，须发布新主版本。插件明确支持该主版本后才接收，兼容规则随包版本维护。
- 取消通过共用入口终止 maa-tools 子进程；已完成且校验通过的用例或文件保留事实，未完成项标跳过。摘要只说明取消，不把部分结果当成整批通过；不同系统的进程退出需要分别验证。
- 即时结果与最终结果必须一致。矛盾、错误来源或不完整快照属于协议错误，同一次调用中已显示的可疑通过也要改为错误，不能因为用户随后取消就保留。
- 编辑辅助依据配置的目录和映射约定工作。自定义图片路径可能与预览不同，用户排错使用运行返回的实际路径。

接口细节见 [reference](../../../skills/maa-node-test-dev/reference.md)，运行摘要的取舍见 [结果摘要记录](../feature/2026-10-27-run-output-summary.md)。
