# Agent Note: 测试面板逐项完成，输出末尾显示摘要

Status: implemented

## Problem

配置加载、资源准备和识别日志可能很长。多文件运行后，用户需要马上知道是否通过、哪些用例出问题；不能靠自己数日志，也不能把“没有返回失败”当成“通过”。

## Decision

- 面板从 `--jsonl` 的标准输出逐行读取结构化事件：用例等本次实际计划的全部平台结束后完成，文件等所选用例全部结束后完成。已完成项不因其他文件仍在运行而继续转圈。
- 保留 stderr 中的原始日志，在运行末尾追加结果摘要。`core/runSummary.ts` 负责文本，`testing.ts` 提供完整的所选用例状态；进度用于提前显示，最后一条 `run-result` 的完整报告补全并核对结果。
- 摘要包含结论、文件与用例计数、实际经过的时间，以及失败、没有完成验证、缺图跳过和未返回结果的条目。通过用例只计数。
- 通过数只来自明确的 pass，不能用总数减去问题数推算。前置错误或缺失结果不得显示通过；未返回结果单独列明。
- 整体结论服从上游文件 verdict。用例在部分平台缺图时可汇总为 skipped，即使所有用例都如此，文件也可能已在其他平台完成验证；这时说明“未在全部平台完成验证”，不说“一条都没验证”。文件 error 才表示该文件没有完成有效验证或发生错误。
- 取消时，面板保留已经完成且校验通过的事实，未完成项标跳过；摘要仍只显示取消和耗时，不给半截运行作整批通过/失败统计。遇到协议矛盾时，不能把可疑的即时结果保留为通过，取消也不覆盖这类错误。
- 用例和文件显示分摊后的识别执行时间，末尾显示运行实际经过的时间，二者不混用。批量和单条操作采用相同摘要结构。

## Alternatives considered

**只留摘要，过滤原始日志。** 配置与框架准备失败的细节可能只在日志里，因此保留日志并在末尾提供可直接阅读的结果。

**把摘要放开头。** 用户跑完时通常停在输出末尾，放在末尾可直接看到最终结果。

**用父节点通过补全所有未返回子节点。** 会掩盖结果缺失、未匹配和部分执行错误。每条所选用例必须有明确状态，否则报错。

**根据缺图用例计数决定整批是否验证过。** 跨平台汇总为 skipped 可能仅因其中一个平台缺图；这种计数不代表实际运行情况，整体结论使用框架文件结果。

## Consequences

摘要是纯文本，不依赖终端颜色或折叠。批量时挂在第一个运行目标上，其余节点显示自己的标记，不重复整批摘要。保留完整日志会增加输出长度，但排错时仍能看到原始原因。
